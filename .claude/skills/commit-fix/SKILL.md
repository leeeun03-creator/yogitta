# 요깃따 버그수정·오류수정 커밋

`commit-convention` 스킬의 5장이다 (장 번호는 그대로 둔다). 목차와 늘 지킬 것은 `commit-convention`에 있다.

## 5. 버그 수정과 오류 수정

작업 중이든 테스트 중이든, **고친 것 하나마다 커밋 하나**. 다른 작업과 섞지 않는다. 첫 줄만 봐도 **어느 부분에서 무엇을** 고쳤는지 보여야 한다.

고친 내용은 같은 커밋에서 문제가 생긴 세부 Todo가 속한 `docs/todo/log/Tn.md`에도 한 줄 남긴다 (`yogitta-todo` 6장).

### 구분

| 종류 | 기준 | 예 |
|---|---|---|
| **버그수정** | 에러는 없는데 동작·결과가 틀림 | 벽이 누워서 생성됨, 검색에 띄어쓰기가 안 먹음, 서랍이 반대쪽으로 열림 |
| **오류수정** | 에러가 남 | 콘솔 빨간 에러, 화면이 하얗게 멈춤, `npm run build` 실패, 타입 오류 |

### 형식

```
Tn-n 버그수정[영역]: <무엇이 어떻게 틀렸는지 / 고친 결과>

- 증상: 사용자가 본 문제
- 원인: 왜 그랬는지
- 해결: 무엇을 바꿨는지
- 발견: 작업 중 | 테스트 중 | 배포 후
```

- `Tn-n` = 그 문제가 **생긴 곳**의 세부 Todo 번호 (다른 Todo 작업 중에 발견해도 원래 번호로)
- 번호를 특정할 수 없는 공통 문제만 번호 없이 `버그수정[영역]:`
- `[영역]`은 아래 목록에서 하나 (첫 줄에서 바로 어디 문제인지 보이게)

| 영역 | 범위 |
|---|---|
| `2D편집` | 2D 평면도, 그리기 도구, 스냅, 선택 핸들 |
| `3D` | 벽·바닥 생성, 카메라, 조명, 3D 클릭 판정 |
| `가구` | 가구 배치, 종류 변신, 회전, 칸, 가구 위 가구 |
| `물건` | 물건 등록·이동·삭제, 가구 상세 패널 |
| `검색` | 검색 매칭, 위치 문장, 요깃따!, 3D 위치 표시 |
| `공간` | 공간 만들기·전환·삭제 |
| `저장` | localStorage, 샘플 데이터, JSON 백업 |
| `UI` | 레이아웃, 반응형, 스타일, 접근성 |
| `빌드` | 빌드·타입·배포 설정 |

### 예시

```
T4-2 버그수정[3D]: 벽이 바닥에 누워서 생성되던 문제

- 증상: 2D에서 그린 벽이 3D에서 바닥에 깔림
- 원인: 2D y를 3D z로 바꾸지 않고 y에 넣음
- 해결: 선분 → 벽 변환에서 (x, y) → (x, 0, y)로 매핑
- 발견: 작업 중
```

```
T11-1 오류수정[저장]: 첫 접속 시 JSON.parse 에러로 화면 멈춤

- 증상: 처음 열면 흰 화면, 콘솔에 SyntaxError
- 원인: 저장된 값이 없을 때 null을 그대로 parse
- 해결: 값이 없으면 샘플 데이터 반환, parse는 try/catch
- 발견: 테스트 중
```

```
T9-1 버그수정[3D]: 화면 회전 후 손을 떼면 가구 패널이 열림

- 증상: 드래그로 돌렸는데 클릭으로 인식
- 원인: pointerup만 보고 클릭 판정
- 해결: 누른 위치와 뗀 위치 거리가 5px 이하일 때만 클릭
- 발견: 테스트 중
```

```
오류수정[빌드]: GitHub Pages에서 JS 파일 404

- 증상: 배포 주소에서 빈 화면
- 원인: Vite base 경로가 / 로 되어 있음
- 해결: vite.config의 base를 /yogitta/로 설정
- 발견: 배포 후
```

> 버그를 고치면서 Todo 자체가 바뀌면(새 세부 Todo가 필요해지는 등) 수정 커밋과 별개로 `todo:` 커밋도 남긴다 (6장).
