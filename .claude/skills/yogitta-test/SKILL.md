# 요깃따 테스트 규칙

세부 Todo마다 테스트 내용은 다르다. 이 스킬은 **모든 세부 Todo에 똑같이 적용하는 공통 규칙**이다.

**기준은 "기능이 제대로 동작하는가"다.** 테스트는 그것을 확인할 만큼만 쓴다. 같은 것을 여러 번 확인하거나, 느낌·모양처럼 사람이 직접 볼 것을 자동 테스트로 늘리지 않는다 (테스트가 많으면 시간과 토큰만 든다).
용어는 `yogitta-code/glossary.md`를 따른다 (코드 테스트, 실제 테스트, 배포 확인, 직접 확인, 엣지 케이스, 완료).

함께 쓰는 스킬
- 작업 흐름 전체 → `yogitta-code` 11장 (이 스킬은 그중 ①계획의 테스트 항목과 ④검사를 맡는다)
- 커밋 → `commit-convention`

---

## 1. 완료 기준

세부 Todo는 **아래를 모두 통과해야 완료**다. 완료 전에는 `docs/todo/Tn.md`에 체크하지 않는다 (`yogitta-todo` 5장).

| # | 검사 | 명령 | 언제 |
|---|---|---|---|
| 1 | 코드 테스트 + 타입·lint·빌드 | `npm run check` | 매 세부 Todo |
| 2 | 실제 테스트 | 바뀐 기능의 spec만 `npx playwright test e2e/… --project=desktop` | 매 세부 Todo. 휴대폰 화면·터치가 바뀌었을 때만 `--project=mobile`도. **전체는 로컬에서 돌리지 않는다** (3의 CI가 돌린다) |
| 3 | 배포 확인 | push 후 GitHub Actions의 `verify` 잡 통과 | 매 push |
| 4 | 직접 확인 | 사용자가 체크리스트(6장)로 확인 | 큰 Todo(Tn) 끝 |

- 망가뜨리기 확인(일부러 고장 내 보기)은 하지 않는다
- 1·2가 통과해야 커밋한다. 3(CI의 실제 테스트 전체)이 실패하면 바로 고친다 (`Tn-n 오류수정[빌드]` 등)
- 체크박스는 1·2를 통과한 커밋에 함께 넣는다

## 2. 다음 작업으로 넘어가는 조건

- 지금 세부 Todo의 테스트가 **모두 통과해야** 다음 세부 Todo로 넘어간다
- **예외**: 지금 Todo를 테스트하려면 다음 Todo가 꼭 있어야 할 때만 (예: store 액션은 화면이 생겨야 실제 테스트 가능)
  - 이때는 계획에 "실제 테스트는 Tn-m에서 함께"라고 적고, 코드 테스트는 지금 통과시킨다
  - 미룬 테스트는 그 Todo에서 반드시 채운다. 미룬 채로 큰 Todo를 끝내지 않는다
- 실패한 테스트를 지우거나 `skip`으로 통과시키지 않는다. `skip`은 환경 때문에 못 돌 때만, 이유 주석과 함께 (예: 배포 주소에서만 되는 검사)

## 3. 계획할 때 — 테스트 항목을 먼저 적는다

`yogitta-code` 11장 ① 계획에 **테스트 항목**을 짧게 같이 보여준다.

- 엣지 케이스는 **코드 테스트**로 확인한다 (빠르고 싸다)
- 실제 테스트는 새 기능마다 **정상 흐름 1~2개**만 쓴다. 코드 테스트로 이미 확인한 것(안내 문구 글자, 계산 결과)은 실제 테스트에서 다시 보지 않는다

```
T2-4 테스트 항목
- 코드 테스트: parseFloorInput — "6.0" → 600cm, "4,5" → 450cm / 엣지: 빈 값, 0, 음수, 범위 밖, "abc"
- 실제 테스트: 빠른 선택 "투룸" → 9.0 / 6.0 → [벽 그리러 가기] → 편집 모드
```

## 4. 엣지 케이스 목록

새 기능에서 **실제로 깨질 만한 것만** 고른다 (주로 코드 테스트로). 목록을 다 채우지 않는다.

| 분류 | 확인할 것 |
|---|---|
| 입력 값 | 빈 값, 공백만, 0, 음수, 소수, 최소·최대 경계(바로 안·바로 밖), 숫자 아닌 글자, 아주 긴 글자 |
| 글자 | 한글 받침 있음·없음, 영어, 숫자로 끝남, 띄어쓰기, 이모지 |
| 목록 | 0개, 1개, 많음(가구 50개·물건 500개), 같은 이름(중복) |
| 상태 | 공간 없음, 가구 없음, 칸 비어 있음, 검색 결과 없음 (`yogitta-design` 8장 문구) |
| 저장 | 저장된 값 없음, 깨진 JSON, 옛 데이터 버전, localStorage 막힘·용량 초과, 새로고침 후 유지 |
| 조작 | 빠르게 두 번 누름, 드래그와 클릭 구분, 되돌리기 끝까지·다시하기 끝까지, 키보드만으로 조작 |
| 화면 | 모바일 360px(가로 스크롤 없음), 넓은 화면 1280px, 글꼴 서버 막힘 |
| 좌표 | 2D y = 3D z, 회전 0·90·180·270도, 바닥 경계 밖으로 나감 |

## 5. 테스트 쓰는 법

### 코드 테스트 (Vitest)
- 대상: `shared/lib`, `features/*/logic`의 순수 함수. 파일은 원본 옆 `이름.test.ts`
- `yogitta-code` 10장 "반드시 테스트할 순수 함수"는 빠짐없이
- 테스트 이름은 한국어 "~한다" (`"받침이 있으면 '은'을 붙인다"`)

### 실제 테스트 (Playwright)
- 파일: `e2e/<feature 또는 화면>.spec.ts`. CI에서는 데스크톱(1280)·모바일(360) 두 화면에서 돌고, 로컬에서는 데스크톱만 돌린다
- 요소 찾기는 사용자가 보는 이름으로: `getByRole`, `getByLabel`, `getByText` 순. `data-testid`는 3D처럼 이름이 없을 때만
  - 역할·이름으로 못 찾으면 접근성(`yogitta-design` 9장)이 빠진 것이니 화면을 고친다
- 모든 실제 테스트는 콘솔 에러가 없는지 함께 본다
- 화면이 **크게** 바뀌는 세부 Todo만 스크린샷 한 장을 찍어(`testInfo.outputPath`) 시안(`yogitta-design` 스킬의 `references/`)과 비교한다
- 3D 캔버스는 픽셀로 판정하지 않는다. 화면 상태(패널 열림, 검색 결과 카드 문구)나 store 상태로 확인하고, 모양은 스크린샷으로 본다
- 데이터가 필요한 테스트는 `localStorage`에 값을 넣고 시작한다 (`page.addInitScript`). 테스트끼리 데이터를 공유하지 않는다

### 배포 확인
- push하면 CI가 배포 뒤 `E2E_BASE_URL=배포 주소`로 실제 테스트를 다시 돌린다
- 로컬에서 직접: `E2E_BASE_URL=https://leeeun03-creator.github.io/yogitta/ npx playwright test`

## 6. 큰 Todo 끝 — 직접 확인 체크리스트

큰 Todo(Tn)의 마지막 세부 Todo가 끝나면, 사용자에게 아래 형식으로 체크리스트를 준다. 사용자가 확인해야 큰 Todo를 완료로 본다.

```
T2 직접 확인 (배포 주소: https://leeeun03-creator.github.io/yogitta/)
- [ ] 처음 열면 첫 실행 화면이 보인다
- [ ] 빠른 선택 "투룸"을 누르면 9.0 × 6.0이 들어간다
- [ ] 가로에 0을 넣으면 버튼이 막히고 안내 문구가 나온다   ← 엣지
- [ ] 휴대폰으로 열어도 카드가 화면 밖으로 나가지 않는다     ← 엣지
```

- 자동 테스트로 확인하기 어려운 것(느낌, 애니메이션, 3D 모양, 실제 휴대폰)을 중심으로 5~10개
- 문제가 나오면 `Tn-n 버그수정[영역]` 커밋으로 고친다 (다시 깨질 만하면 테스트 하나를 더한다)

## 7. 실패했을 때

1. 테스트가 맞고 코드가 틀림 → 코드를 고치고 `Tn-n 버그수정[영역]` / `Tn-n 오류수정[영역]` 커밋 (`commit-convention` 5장)
2. 테스트가 틀림 (환경 차이, 잘못된 기대값) → 이유를 사용자에게 말하고 테스트를 고친다. 이유는 테스트 주석에 남긴다
3. 원인을 모름 → 추측으로 고치지 않고, 재현 → 원인 확인 → 수정 순서로 간다

## 8. 보고

세부 Todo를 끝낼 때 보고에 테스트 결과를 한 줄로 넣는다.

```
테스트: 코드 12개 통과 · 실제 2개 통과(데스크톱)
```

## 9. 하지 말 것

- 테스트를 안 돌리고 체크박스 체크, 커밋
- 실패한 테스트 삭제·`skip`으로 통과시키기
- 로컬에서 실제 테스트 전체 돌리기, 망가뜨리기 확인, 같은 것을 코드 테스트와 실제 테스트로 두 번 확인하기
- 테스트 때문에 화면 코드에 테스트 전용 분기 넣기
