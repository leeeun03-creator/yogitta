# 요깃따 Todo 규칙

Todo는 "할 일을 적는 것"보다 **바로 시작할 수 있는 단위로 쪼개는 것**이 핵심이다.
PRD 기능(F) → 유저 스토리(US) → 큰 Todo(`Tn`) → 세부 Todo(`Tn-n`) 순서로 내려간다.

함께 쓰는 스킬
- 완료 기준·테스트 → `yogitta-test`
- 번호 규칙·커밋 형식 → `commit-convention`
- 용어 → `yogitta-code/glossary.md` (목표, 오늘 할 일, 큰 Todo, 세부 Todo, 세부 Todo 파일)

---

## 1. 파일 구조

```
docs/
├─ TODO.md        전체를 한눈에: 목표 · 오늘 할 일 · 챕터별 큰 Todo 목록
└─ todo/
   ├─ T1.md       큰 Todo 하나 = 세부 Todo 파일 하나 (큰 Todo를 시작할 때 만든다)
   ├─ T2.md
   └─ log/        Todo 변경 로그 (필요할 때만 본다)
      ├─ T1.md    큰 Todo별 로그: 세부 Todo 변경, 버그수정·오류수정
      ├─ T2.md
      └─ 전체.md  여러 큰 Todo에 걸친 변경: 우선순위 재조정, 챕터 재배치, Todo 구조
```

| 파일 | 들어가는 것 | 들어가지 않는 것 |
|---|---|---|
| `docs/TODO.md` | 목표 표, 오늘 할 일(MIT), 챕터별 큰 Todo 한 줄씩(완료 기준·우선순위·의존·진행 수·링크), 로그 폴더 링크 | 세부 Todo 체크박스, 변경 기록 |
| `docs/todo/Tn.md` | 큰 Todo 정보, 로그 링크, 세부 Todo 체크박스 + 완료 조건, 테스트 결과, 직접 확인 체크리스트, 메모 | 다른 큰 Todo의 내용, 변경 기록 |
| `docs/todo/log/Tn.md` | 그 큰 Todo의 세부 Todo 추가·삭제·수정, 버그수정·오류수정 (날짜·대상·변경·내용·이유) | 다른 큰 Todo의 기록 |
| `docs/todo/log/전체.md` | 큰 Todo 여러 개에 걸친 변경 | 큰 Todo 하나에만 해당하는 기록 |

- **세부 Todo 체크박스는 `docs/todo/Tn.md`에만** 둔다. 같은 체크박스를 두 곳에 두지 않는다
- `docs/TODO.md`의 큰 Todo 줄에는 진행 수(`진행 2/6`)와 링크(`[세부 Todo](todo/T2.md)`)만 둔다

## 2. 시작할 때 읽는 순서

세션을 시작하거나 "이어서 해줘"를 받으면, 코드를 보기 전에 이 순서로 읽는다.

1. `docs/TODO.md` — 목표 표, 오늘 할 일, 체크 안 된 첫 큰 Todo
2. 그 큰 Todo의 `docs/todo/Tn.md` — 체크 안 된 첫 세부 Todo, 그 의존이 모두 끝났는지
3. 그 세부 Todo의 완료 조건에 나온 PRD 항목(F·US·인수 조건)
4. 마지막 커밋 몇 개 (`git log --oneline -5`) — 체크와 실제 커밋이 맞는지

읽은 뒤 사용자에게 **3줄로** 보고하고 시작한다.

```
지금: 챕터 1. 기반 — T2 진행 2/6 (목표 "배포 주소에서 …")
다음: T2-3 첫 실행 화면 만들기 — 완료: … · 의존 T2-2 ✓
막힌 것: 없음 (또는: T1 직접 확인 대기)
```

- 체크와 커밋이 안 맞으면(체크됐는데 커밋 없음, 커밋됐는데 체크 안 됨) 먼저 사용자에게 말한다
- 의존이 안 끝났으면 그 세부 Todo를 시작하지 않는다 (`yogitta-test` 2장 예외만 허용)

## 3. 큰 Todo 쓰는 법 (`docs/TODO.md`)

전체 과정은 **큰 Todo로 미리** 나누고, 만드는 순서(의존 순서)대로 **챕터**로 묶는다. 일차와 예상 시간은 적지 않는다.

```
### 2. 벽과 3D

목표: 2D 평면도에 그린 벽이 3D 미리보기에서 같은 자리에 선다

- [ ] **T3. …**
- [ ] **T4. …**
```

- 챕터마다 끝나면 도달할 **목표**를 한 줄 붙인다. 목표 표(`docs/TODO.md` 맨 위)와 같게
- P0는 "제출 가능" 목표가 있는 챕터까지 모두 들어가야 한다. P1은 그 뒤 챕터, P2는 "여유 있으면"

큰 Todo 한 줄:

```
- [ ] **T3. 벽 그리기 도구 만들기** (직선·연속선·사각형·지우개) · P0 · 의존 T2 · 진행 0/5 · [세부 Todo](todo/T3.md)
  - PRD: F2 / US3
  - 완료 기준: 네 도구로 그린 벽이 점 목록으로 저장되고 2D 평면도에 보이며, 지우개로 선분을 지울 수 있다
```

| 항목 | 규칙 |
|---|---|
| 제목 | 동사로 끝낸다: "벽 그리기 도구 만들기" (✗ "벽 도구") |
| 번호 | 기획서 6장과 같게. 새로 생기면 다음 번호 (`commit-convention` 1장) |
| 연결 | PRD 기능(F)·유저 스토리(US)·인수 조건 |
| 완료 기준 | PRD 인수 조건에서 가져온다. 끝났는지 바로 판단할 수 있게 |
| 우선순위 | PRD 6장 P0 · P1 · P2 |
| 챕터 | 만드는 순서대로 묶은 단계. 의존하는 큰 Todo보다 앞 챕터에 두지 않는다 |
| 의존 | 먼저 끝나야 하는 큰 Todo |

## 4. 세부 Todo 쓰는 법 (`docs/todo/Tn.md`)

세부 Todo는 **큰 Todo를 시작할 때** 파일을 만들고 모두 적은 뒤, `todo:` 커밋으로 먼저 올리고 시작한다.

```markdown
---
todo: T3
updated: 2026-10-29
---

# T3. 벽 그리기 도구 만들기

챕터 2. 벽과 3D · P0 · 의존 T2 · PRD F2 / US3
완료 기준: 네 도구로 그린 벽이 점 목록으로 저장되고 2D 평면도에 보이며, 지우개로 선분을 지울 수 있다
변경 로그: [log/T3.md](log/T3.md)

## 세부 Todo

- [ ] T3-1 직선 도구로 벽 하나 그리기
  - 완료: 두 번 누르면 점 2개짜리 벽이 저장·표시된다. 엣지 — 같은 자리 두 번(길이 0)은 무시, 바닥 밖 점은 바닥 경계로 · 의존 T2-6
- [ ] T3-2 연속선 도구로 꺾인 벽 그리기
  - 완료: … · 의존 T3-1

## 직접 확인

(마지막 세부 Todo가 끝나면 `yogitta-test` 6장 체크리스트를 여기에 적는다)

## 메모

(작업 중 알게 된 것, 미룬 테스트, 다음 Todo에 넘길 것)

```

| 항목 | 규칙 |
|---|---|
| 제목 | 동사로 끝낸다: "직선 도구로 벽 하나 그리기" (✗ "직선 도구") |
| 완료 조건 | **통과해야 할 테스트**로 쓴다: 정상 + 엣지 케이스 (`yogitta-test` 3·4장) |
| 크기 | 큰 Todo 하나를 3~4개로 나눈다 (시간은 적지 않는다). 하나가 화면이나 테스트로 확인할 수 있는 단위여야 한다 |
| 의존 | 앞 세부 Todo 또는 다른 큰 Todo의 세부 Todo |
| 끝 단위 | 끝나면 화면이나 테스트로 확인할 수 있는 단위 |

## 5. 체크할 때

- 세부 Todo의 테스트를 모두 통과한 커밋에서 `docs/todo/Tn.md`의 `[ ]`를 `[x]`로 바꾸고, 그 아래에 결과 한 줄을 붙인다
  ```
  - [x] T2-1 데이터 모델 타입과 단위 상수 정의하기
    - 완료: …
    - 결과: 코드 4개 통과 · 실제 12개 통과 · 커밋 `T2-1: …`
  ```
- 같은 커밋에서 `docs/TODO.md` 큰 Todo 줄의 진행 수를 올린다
- 세부 Todo가 모두 체크되고 직접 확인(`yogitta-test` 6장)까지 받으면 큰 Todo를 체크한다

## 6. 바뀔 때 — 로그 쓰기

Todo를 바꾸거나 버그·오류를 고치면 **같은 커밋에** `docs/todo/log/`에 한 줄 남긴다. 로그는 Todo 파일과 따로 두고 필요할 때만 본다.

| 무엇이 바뀌었나 | 로그 파일 |
|---|---|
| 세부 Todo 추가·삭제·수정, 버그수정·오류수정, 큰 Todo 하나의 변경 | `docs/todo/log/Tn.md` (문제가 **생긴** 큰 Todo) |
| 큰 Todo 여러 개에 걸친 변경, Todo 구조 변경 | `docs/todo/log/전체.md` |

- 커밋: Todo 변경은 `todo:`, 버그·오류는 `Tn-n 버그수정[영역]` / `Tn-n 오류수정[영역]` (`commit-convention` 5·6장)
- **로그를 쓸 때는 `references/log.md`를 연다** (로그 파일 틀, 칸 설명, 변경 종류, 예시)

## 7. 목표 · 오늘 할 일 · 하루 마무리

- **목표**는 할 일이 아니다 ("P0 완료 = 제출 가능"). `docs/TODO.md`의 "목표" 표에 따로 둔다
- **오늘 할 일(MIT)**: 그날 꼭 끝낼 세부 Todo 1~3개만 적는다
- **하루 양**: 할 수 있다고 생각하는 양의 70% 정도만 오늘 할 일에 넣는다
- **하루 마무리**: 남은 오늘 할 일을 다음 날로 옮기거나 지우고, 제출이 가까운데 밀렸으면 P2 → P1 순으로 빼서 로그(`log/전체.md`)에 남긴다 (`todo:` 커밋)

## 8. 하지 말 것

- 목표를 할 일로 적기 ("검색 잘 되게 하기" ✗ → "검색어 띄어쓰기 무시하기" ✓)
- 완료 조건 없이 세부 Todo 적기
- 큰 Todo를 세부 Todo 5개 넘게 잘게 쪼개기, 쪼개지 않고 시작하기
- 같은 체크박스를 두 파일에 두기
- 변경 기록을 `docs/TODO.md`나 세부 Todo 파일에 적기 (기록은 `docs/todo/log/`에만)
- 테스트를 통과하지 않았는데 체크하기
- 세부 Todo를 적지 않고 큰 Todo 작업 시작하기
