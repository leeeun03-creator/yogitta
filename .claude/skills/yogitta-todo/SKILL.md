# 요깃따 Todo 규칙

Todo는 "할 일을 적는 것"보다 **바로 시작할 수 있는 단위로 쪼개는 것**이 핵심이다.
PRD 기능(F) → 유저 스토리(US) → 큰 Todo(`Tn`) → 세부 Todo(`Tn-n`) 순서로 내려간다.

함께 쓰는 스킬
- 완료 기준·테스트 → `yogitta-test`
- 번호 규칙·커밋 형식 → `commit-convention`
- 용어 → `yogitta-code/glossary.md` (목표, 오늘 할 일, 큰 Todo, 세부 Todo, 세부 Todo 파일)

---

## 1. 파일 구조

```
docs/
├─ TODO.md        전체를 한눈에: 목표 · 오늘 할 일 · 큰 Todo 목록 · Todo 변경 내역
└─ todo/
   ├─ T1.md       큰 Todo 하나 = 세부 Todo 파일 하나
   ├─ T2.md
   └─ …           큰 Todo를 시작할 때 만든다
```

| 파일 | 들어가는 것 | 들어가지 않는 것 |
|---|---|---|
| `docs/TODO.md` | 목표 표, 오늘 할 일(MIT), 큰 Todo 한 줄씩(완료 기준·일차·시간·의존·진행 수·링크), Todo 변경 내역 | 세부 Todo 체크박스 |
| `docs/todo/Tn.md` | 큰 Todo 정보, 세부 Todo 체크박스 + 완료 조건, 테스트 결과, 직접 확인 체크리스트, 메모 | 다른 큰 Todo의 내용 |

- **세부 Todo 체크박스는 `docs/todo/Tn.md`에만** 둔다. 같은 체크박스를 두 곳에 두지 않는다
- `docs/TODO.md`의 큰 Todo 줄에는 진행 수(`진행 2/6`)와 링크(`[세부 Todo](todo/T2.md)`)만 둔다

## 2. 시작할 때 읽는 순서

세션을 시작하거나 "이어서 해줘"를 받으면, 코드를 보기 전에 이 순서로 읽는다.

1. `docs/TODO.md` — 목표 표, 오늘 할 일, 체크 안 된 첫 큰 Todo
2. 그 큰 Todo의 `docs/todo/Tn.md` — 체크 안 된 첫 세부 Todo, 그 의존이 모두 끝났는지
3. 그 세부 Todo의 완료 조건에 나온 PRD 항목(F·US·인수 조건)
4. 마지막 커밋 몇 개 (`git log --oneline -5`) — 체크와 실제 커밋이 맞는지

읽은 뒤 사용자에게 **3줄로** 보고하고 시작한다.

```
지금: T2 진행 2/6 (1일차, 목표 "배포 주소에서 …")
다음: T2-3 첫 실행 화면 만들기 — 완료: … · 1.5h · 의존 T2-2 ✓
막힌 것: 없음 (또는: T1 직접 확인 대기, 일정 ⚠ 6일차 12h)
```

- 체크와 커밋이 안 맞으면(체크됐는데 커밋 없음, 커밋됐는데 체크 안 됨) 먼저 사용자에게 말한다
- 의존이 안 끝났으면 그 세부 Todo를 시작하지 않는다 (`yogitta-test` 2장 예외만 허용)

## 3. 큰 Todo 쓰는 법 (`docs/TODO.md`)

전체 과정은 **큰 Todo로 미리** 나눈다. 일차 순서로 놓는다.

```
- [ ] **T3. 벽 그리기 도구 만들기** (직선·연속선·사각형·지우개) · P0 · 2일차 · 5h · 의존 T2 · 진행 0/5 · [세부 Todo](todo/T3.md)
  - PRD: F2 / US3
  - 완료 기준: 네 도구로 그린 벽이 점 목록으로 저장되고 2D 평면도에 보이며, 지우개로 선분을 지울 수 있다
```

| 항목 | 규칙 |
|---|---|
| 제목 | 동사로 끝낸다: "벽 그리기 도구 만들기" (✗ "벽 도구") |
| 번호 | 기획서 6장과 같게. 새로 생기면 다음 번호 (`commit-convention` 1장) |
| 연결 | PRD 기능(F)·유저 스토리(US)·인수 조건 |
| 완료 기준 | PRD 인수 조건에서 가져온다. 끝났는지 바로 판단할 수 있게 |
| 우선순위 | PRD 6장 P0 · P1 · P2 |
| 크기 | 일차 + 예상 시간 |
| 의존 | 먼저 끝나야 하는 큰 Todo |

## 4. 세부 Todo 쓰는 법 (`docs/todo/Tn.md`)

세부 Todo는 **큰 Todo를 시작할 때** 파일을 만들고 모두 적은 뒤, `todo:` 커밋으로 먼저 올리고 시작한다.

```markdown
---
todo: T3
updated: 2026-10-29
---

# T3. 벽 그리기 도구 만들기

P0 · 2일차 · 5h · 의존 T2 · PRD F2 / US3
완료 기준: 네 도구로 그린 벽이 점 목록으로 저장되고 2D 평면도에 보이며, 지우개로 선분을 지울 수 있다

## 세부 Todo

- [ ] T3-1 직선 도구로 벽 하나 그리기
  - 완료: 두 번 누르면 점 2개짜리 벽이 저장·표시된다. 엣지 — 같은 자리 두 번(길이 0)은 무시, 바닥 밖 점은 바닥 경계로 · 1.5h · 의존 T2-6
- [ ] T3-2 연속선 도구로 꺾인 벽 그리기
  - 완료: … · 1.5h · 의존 T3-1

## 직접 확인

(마지막 세부 Todo가 끝나면 `yogitta-test` 6장 체크리스트를 여기에 적는다)

## 메모

(작업 중 알게 된 것, 미룬 테스트, 다음 Todo에 넘길 것)
```

| 항목 | 규칙 |
|---|---|
| 제목 | 동사로 끝낸다: "직선 도구로 벽 하나 그리기" (✗ "직선 도구") |
| 완료 조건 | **통과해야 할 테스트**로 쓴다: 정상 + 엣지 케이스 (`yogitta-test` 3·4장) |
| 크기 | 30분~2시간. 넘으면 쪼개고, 5분짜리는 묶는다 |
| 의존 | 앞 세부 Todo 또는 다른 큰 Todo의 세부 Todo |
| 끝 단위 | 끝나면 화면이나 테스트로 확인할 수 있는 단위 |

## 5. 체크할 때

- 세부 Todo의 테스트를 모두 통과한 커밋에서 `docs/todo/Tn.md`의 `[ ]`를 `[x]`로 바꾸고, 그 아래에 결과 한 줄을 붙인다
  ```
  - [x] T2-1 데이터 모델 타입과 단위 상수 정의하기
    - 완료: … · 1h
    - 결과: 코드 4개 통과 · 실제 12개 통과 · 커밋 `T2-1: …`
  ```
- 같은 커밋에서 `docs/TODO.md` 큰 Todo 줄의 진행 수를 올린다
- 세부 Todo가 모두 체크되고 직접 확인(`yogitta-test` 6장)까지 받으면 큰 Todo를 체크한다

## 6. 바뀔 때

세부 Todo나 큰 Todo를 추가·삭제·수정하거나 우선순위·일차를 바꾸면:

1. 해당 파일(`docs/TODO.md` 또는 `docs/todo/Tn.md`)을 고친다
2. `docs/TODO.md` 맨 아래 "Todo 변경 내역" 표에 한 줄 추가 (날짜 · 변경 종류 · 내용 · 이유)
3. 코드와 따로 `todo:` 커밋 (`commit-convention` 6장)

- 변경 종류: 추가 · 삭제 · 수정 · 상향 · 하향 · 분할 · 병합
- 번호는 재사용하지 않는다. 지운 번호는 비워둔다

## 7. 목표 · 오늘 할 일 · 하루 마무리

- **목표**는 할 일이 아니다 ("P0 완료 = 제출 가능"). `docs/TODO.md`의 "목표" 표에 따로 둔다
- **오늘 할 일(MIT)**: 그날 꼭 끝낼 세부 Todo 1~3개만 적는다
- **하루 양**: 하루 합계는 하루 작업량(약 7시간)의 70% 안쪽. 넘으면 일차 제목에 ⚠를 붙이고 사용자와 조정한다
- **하루 마무리**: 남은 오늘 할 일을 다음 날로 옮기거나 지우고, 일정이 밀렸으면 P2 → P1 순으로 빼서 변경 내역에 남긴다 (`todo:` 커밋)

## 8. 하지 말 것

- 목표를 할 일로 적기 ("검색 잘 되게 하기" ✗ → "검색어 띄어쓰기 무시하기" ✓)
- 완료 조건 없이 세부 Todo 적기
- 2시간 넘는 세부 Todo, 쪼개지 않고 시작하기
- 같은 체크박스를 두 파일에 두기
- 테스트를 통과하지 않았는데 체크하기
- 세부 Todo를 적지 않고 큰 Todo 작업 시작하기
