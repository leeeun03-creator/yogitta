# 요깃따 커밋 메시지 형식

`commit-convention` 스킬의 1·3·4장이다 (장 번호는 그대로 둔다). 목차와 늘 지킬 것은 `commit-convention`에 있다.

## 1. Todo 번호 체계

```
T3. 벽 도구                 ← 큰 Todo (`docs/TODO.md`)
  T3-1. 직선 도구            ← 세부 Todo = 커밋 단위
  T3-2. 연속 직선 도구
  T3-3. 사각형 도구
  T3-4. 지우개
```

- 큰 Todo `Tn`의 번호는 기획서·PRD와 같게 유지
- 세부 Todo `Tn-n`은 큰 Todo를 시작할 때 `docs/todo/Tn.md`에 먼저 적고 시작 (쓰는 법은 `yogitta-todo` 스킬)
- 세부 Todo 하나 = 큰 Todo를 3~4개로 나눈 크기, 끝나면 화면에서 확인 가능한 단위
- 번호는 재사용하지 않는다. 지운 세부 Todo 번호는 비워두고, 새로 생긴 것은 다음 번호 (`T3-5`)

Todo를 읽고 쓰는 법(파일 구조, 동사형 제목, 완료 조건, 크기, 의존, 오늘 할 일)은 `yogitta-todo` 스킬을 따른다.

## 3. 메시지 형식

```
Tn-n: <작업 내용 한 줄, 50자 안쪽>

- 바뀐 점 1
- 바뀐 점 2
```

- 첫 줄 = 세부 Todo 번호 + 실제로 한 작업
- 한국어, "~구현", "~추가", "~수정"처럼 명사형으로 끝내고 마침표 없음
- 본문 bullet은 사람이 바로 이해할 수 있게 (파일 이름 나열 금지)
- 큰 Todo의 마지막 세부 Todo를 끝냈으면 본문 마지막 줄에 `T3 완료`

### 머리말 종류

| 머리말 | 언제 | 예시 |
|---|---|---|
| `Tn-n` | 세부 Todo 작업 | `T3-3: 드래그로 사각형 벽 그리기 구현` |
| `Tn-n 버그수정[영역]` | 동작이 틀림 (에러는 안 나지만 결과가 이상) | `T7-2 버그수정[가구]: 회전한 서랍장이 2D와 3D에서 위치가 다름` |
| `Tn-n 오류수정[영역]` | 에러가 남 (콘솔 에러, 화면 멈춤, 빌드·타입 오류) | `T11-1 오류수정[저장]: 저장 데이터 없을 때 JSON.parse 에러` |
| `todo` | Todo 리스트 자체가 바뀜 | `todo: T29-3 가구 위 가구 같이 이동을 P2로` |
| `docs` | README, 기획서, PRD (Todo 리스트 변경은 `todo`) | `docs: README에 스킬 사용 내역 추가` |
| `chore` | 설정, 배포, 패키지 | `chore: GitHub Pages 배포 설정` |
| `skill` | `.claude/skills/` 안의 스킬 추가·수정 | `skill: 디자인 규칙에 핀 라벨 크기 추가` |

세부 Todo가 없는 작업(설정, 문서)만 `docs` · `chore` · `skill`을 쓴다. 기능 코드는 반드시 `Tn-n`.

## 4. 예시

```
T3-3: 드래그로 사각형 벽 그리기 구현

- 드래그하면 벽 4개(닫힌 점 목록)로 저장
- 그리는 중 미리보기 선 표시
```

```
T3-4: 지우개로 벽 선분 삭제 구현

- 선분 클릭 시 해당 벽만 삭제, 사각형은 4개 선분 단위로 삭제
T3 완료
```

```
T10-2: 받침에 따라 은/는 자동 선택

- 마지막 글자 유니코드로 받침 판별
- "여권은" / "보조배터리는" 확인
```

버그·오류 수정 예시는 5장.
