# 요깃따 커밋 규칙

과제 조건 두 가지를 지키기 위한 스킬이다.
- 다 만들고 한 번에 push하지 말고, **Todo로 작업하는 중간중간 push**
- 커밋 내역에 **무엇을 했는지가 반드시 보이게**

그래서 커밋 단위는 **세부 Todo(Tn-n) 하나**다. 커밋 로그만 봐도 어떤 Todo의 몇 번째 작업을 했는지 보이고, `docs/todo/log/`의 Todo 변경 로그를 커밋 로그에서 바로 정리할 수 있어야 한다.

## 1. Todo 번호 체계

```
T3. 벽 도구                 ← 큰 Todo (`docs/TODO.md`)
  T3-1. 직선 도구            ← 세부 Todo = 커밋 단위
  T3-2. 연속 직선 도구
  T3-3. 사각형 도구
  T3-4. 지우개
```

- 큰 Todo `Tn`의 번호는 기획서·PRD와 같게 유지
- 세부 Todo `Tn-n`은 큰 Todo를 시작할 때 `docs/todo/Tn.md`에 먼저 적고 시작 (쓰는 법은 `yogitta-todo` 스킬)
- 세부 Todo 하나 = 30분~2시간에 끝나는 크기, 끝나면 화면에서 확인 가능한 단위
- 번호는 재사용하지 않는다. 지운 세부 Todo 번호는 비워두고, 새로 생긴 것은 다음 번호 (`T3-5`)

Todo를 읽고 쓰는 법(파일 구조, 동사형 제목, 완료 조건, 크기, 의존, 오늘 할 일)은 `yogitta-todo` 스킬을 따른다.

## 2. 언제 커밋하나

| 상황 | 커밋 |
|---|---|
| 세부 Todo(Tn-n) 하나를 끝냈을 때 | 반드시 커밋 + push |
| 작업 중·테스트 중 버그나 오류를 고쳤을 때 | 고친 것 하나마다 따로 커밋 (5장 형식) |
| 세부 Todo를 추가·삭제·수정·순서 변경했을 때 | `todo:` 커밋 (6장) |
| 하루 작업 끝 | 최소 1회 push. 빌드가 되는 상태로 |

- 한 커밋 = 세부 Todo 하나. `T3-1`과 `T3-2`를 한 커밋에 섞지 않는다
- 빌드가 깨진 상태로는 커밋하지 않는다

## 3. 메시지 형식

```
Tn-n: <작업 내용 한 줄, 50자 안쪽>

- 바뀐 점 1
- 바뀐 점 2
```

- 첫 줄 = 세부 Todo 번호 + 실제로 한 작업
- 한국어, "~구현", "~추가", "~수정"처럼 명사형으로 끝내고 마침표 없음
- 본문 bullet은 사람이 바로 이해할 수 있게 (파일 이름 나열 금지)
- 큰 Todo의 마지막 세부 Todo를 끝냈으면 본문 마지막 줄에 `T3 완료`

### 머리말 종류

| 머리말 | 언제 | 예시 |
|---|---|---|
| `Tn-n` | 세부 Todo 작업 | `T3-3: 드래그로 사각형 벽 그리기 구현` |
| `Tn-n 버그수정[영역]` | 동작이 틀림 (에러는 안 나지만 결과가 이상) | `T7-2 버그수정[가구]: 회전한 서랍장이 2D와 3D에서 위치가 다름` |
| `Tn-n 오류수정[영역]` | 에러가 남 (콘솔 에러, 화면 멈춤, 빌드·타입 오류) | `T11-1 오류수정[저장]: 저장 데이터 없을 때 JSON.parse 에러` |
| `todo` | Todo 리스트 자체가 바뀜 | `todo: T29-3 가구 위 가구 같이 이동을 P2로` |
| `docs` | README, 기획서, PRD (Todo 리스트 변경은 `todo`) | `docs: README에 스킬 사용 내역 추가` |
| `chore` | 설정, 배포, 패키지 | `chore: GitHub Pages 배포 설정` |
| `skill` | `.claude/skills/` 안의 스킬 추가·수정 | `skill: 디자인 규칙에 핀 라벨 크기 추가` |

세부 Todo가 없는 작업(설정, 문서)만 `docs` · `chore` · `skill`을 쓴다. 기능 코드는 반드시 `Tn-n`.

## 4. 예시

```
T3-3: 드래그로 사각형 벽 그리기 구현

- 드래그하면 벽 4개(닫힌 점 목록)로 저장
- 그리는 중 미리보기 선 표시
```

```
T3-4: 지우개로 벽 선분 삭제 구현

- 선분 클릭 시 해당 벽만 삭제, 사각형은 4개 선분 단위로 삭제
T3 완료
```

```
T10-2: 받침에 따라 은/는 자동 선택

- 마지막 글자 유니코드로 받침 판별
- "여권은" / "보조배터리는" 확인
```

버그·오류 수정 예시는 5장.

## 5. 버그 수정과 오류 수정

작업 중이든 테스트 중이든, **고친 것 하나마다 커밋 하나**. 다른 작업과 섞지 않는다. 첫 줄만 봐도 **어느 부분에서 무엇을** 고쳤는지 보여야 한다.

고친 내용은 같은 커밋에서 문제가 생긴 세부 Todo가 속한 `docs/todo/log/Tn.md`에도 한 줄 남긴다 (`yogitta-todo` 6장).

### 구분

| 종류 | 기준 | 예 |
|---|---|---|
| **버그수정** | 에러는 없는데 동작·결과가 틀림 | 벽이 누워서 생성됨, 검색에 띄어쓰기가 안 먹음, 서랍이 반대쪽으로 열림 |
| **오류수정** | 에러가 남 | 콘솔 빨간 에러, 화면이 하얗게 멈춤, `npm run build` 실패, 타입 오류 |

### 형식

```
Tn-n 버그수정[영역]: <무엇이 어떻게 틀렸는지 / 고친 결과>

- 증상: 사용자가 본 문제
- 원인: 왜 그랬는지
- 해결: 무엇을 바꿨는지
- 발견: 작업 중 | 테스트 중 | 배포 후
```

- `Tn-n` = 그 문제가 **생긴 곳**의 세부 Todo 번호 (다른 Todo 작업 중에 발견해도 원래 번호로)
- 번호를 특정할 수 없는 공통 문제만 번호 없이 `버그수정[영역]:`
- `[영역]`은 아래 목록에서 하나 (첫 줄에서 바로 어디 문제인지 보이게)

| 영역 | 범위 |
|---|---|
| `2D편집` | 2D 평면도, 그리기 도구, 스냅, 선택 핸들 |
| `3D` | 벽·바닥 생성, 카메라, 조명, 3D 클릭 판정 |
| `가구` | 가구 배치, 종류 변신, 회전, 칸, 가구 위 가구 |
| `물건` | 물건 등록·이동·삭제, 가구 상세 패널 |
| `검색` | 검색 매칭, 위치 문장, 요깃따!, 3D 위치 표시 |
| `공간` | 공간 만들기·전환·삭제 |
| `저장` | localStorage, 샘플 데이터, JSON 백업 |
| `UI` | 레이아웃, 반응형, 스타일, 접근성 |
| `빌드` | 빌드·타입·배포 설정 |

### 예시

```
T4-2 버그수정[3D]: 벽이 바닥에 누워서 생성되던 문제

- 증상: 2D에서 그린 벽이 3D에서 바닥에 깔림
- 원인: 2D y를 3D z로 바꾸지 않고 y에 넣음
- 해결: 선분 → 벽 변환에서 (x, y) → (x, 0, y)로 매핑
- 발견: 작업 중
```

```
T11-1 오류수정[저장]: 첫 접속 시 JSON.parse 에러로 화면 멈춤

- 증상: 처음 열면 흰 화면, 콘솔에 SyntaxError
- 원인: 저장된 값이 없을 때 null을 그대로 parse
- 해결: 값이 없으면 샘플 데이터 반환, parse는 try/catch
- 발견: 테스트 중
```

```
T9-1 버그수정[3D]: 화면 회전 후 손을 떼면 가구 패널이 열림

- 증상: 드래그로 돌렸는데 클릭으로 인식
- 원인: pointerup만 보고 클릭 판정
- 해결: 누른 위치와 뗀 위치 거리가 5px 이하일 때만 클릭
- 발견: 테스트 중
```

```
오류수정[빌드]: GitHub Pages에서 JS 파일 404

- 증상: 배포 주소에서 빈 화면
- 원인: Vite base 경로가 / 로 되어 있음
- 해결: vite.config의 base를 /yogitta/로 설정
- 발견: 배포 후
```

> 버그를 고치면서 Todo 자체가 바뀌면(새 세부 Todo가 필요해지는 등) 수정 커밋과 별개로 `todo:` 커밋도 남긴다 (6장).

## 6. Todo가 바뀔 때 (`docs/todo/log/` 로그용)

세부 Todo를 추가·삭제·수정하거나 우선순위를 바꾸면 **코드와 따로** `todo:` 커밋을 만든다. 본문에 이유와 변경 전후를 반드시 쓴다.

```
todo: T3-5 연속 직선 끝점 스냅 추가

- 이유: 테스트해보니 벽 끝이 안 맞아서 틈이 생김
- 추가: T3-5 연속 직선 끝점 스냅 (P1)
```

```
todo: T18-1 벽 모서리 이음새를 P2로 하향

- 이유: 기둥 박스로 가리니 눈에 띄지 않음
- 변경 전: P1 / 변경 후: P2
```

- 변경 종류는 `추가` · `삭제` · `수정` · `상향` · `하향` · `분할` · `병합` 중 하나
- 같은 커밋에서 로그도 함께 남긴다: `docs/todo/log/Tn.md`, 여러 큰 Todo에 걸치면 `log/전체.md` (`yogitta-todo` 6장)

## 7. 순서 (Claude가 커밋할 때)

1. 지금 끝낸 세부 Todo 번호 확인 (`docs/todo/Tn.md`에 없으면 먼저 `todo:` 커밋으로 추가)
2. `git status`로 바뀐 파일 확인
3. `npm run check`와 `npm run test:e2e` 통과 확인 (실패하면 커밋하지 않고 먼저 고친다, `yogitta-test` 1장)
4. 관련 파일만 `git add <파일>`
5. `Tn-n: 작업 내용` 형식으로 `git commit`
6. `docs/todo/Tn.md`에서 해당 세부 Todo 체크 + 결과 한 줄, `docs/TODO.md` 진행 수 올리기 (`yogitta-todo` 5장) (`- [x] T3-3 사각형 도구`) — 같은 커밋에 포함
7. `git push`
8. 사용자에게 한 줄 보고: 커밋 첫 줄 + 다음 세부 Todo

커밋하지 않는 것: `node_modules/`, `dist/`(배포 브랜치 제외), `.env`, 개인 메모, 비밀번호·토큰

## 8. README용으로 로그 뽑기

```bash
git log --pretty=format:"%ad | %s" --date=short                    # 전체 흐름
git log --pretty=format:"%ad | %s" --date=short --grep="^todo:"    # Todo 변경만 (내용은 docs/todo/log/)
git log --pretty=format:"%s" --grep="^T3-"                         # T3의 세부 작업만
git log --pretty=format:"%ad | %s" --date=short --grep="버그수정\|오류수정"   # 고친 것 전체
git log --pretty=format:"%s" --grep="\[3D\]"                        # 3D 영역에서 고친 것만
```
