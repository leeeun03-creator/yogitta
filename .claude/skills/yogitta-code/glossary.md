# 요깃따 용어집

주석, README, 커밋 메시지, 기획서, 화면 문구에서 **같은 것은 항상 같은 단어**로 쓴다.
"쓰지 않는 말" 칸의 단어가 보이면 "쓰는 말"로 바꾼다. 새 개념이 생기면 먼저 이 표에 추가하고 쓴다.

## 데이터

| 쓰는 말 | 코드 이름 | 뜻 | 쓰지 않는 말 |
|---|---|---|---|
| 전체 데이터 | `AppData` | 저장되는 모든 것 (공간 목록 + 현재 공간) | 집, 앱 데이터, DB |
| 공간 | `Space` | 벽·가구·물건 한 세트. "내 방", "형 방"처럼 사용자가 이름 붙인 단위 | 방, 집, 맵, 레이아웃, 구조 |
| 현재 공간 | `currentSpaceId` | 지금 보고 있는 공간 | 선택된 방, 활성 공간 |
| 구역 | `rooms`, `room` | 공간 안을 나눈 이름 (안방, 거실). 선택 사항 | 방, 영역, 존 |
| 구역 선 | `roomLines` | 구역을 나누려고 2D 평면도에 손 가는 대로 긋는 선. 10cm 격자를 따라 경계가 되고, 3D에는 서지 않는다 | 경계선, 구분선, 파티션, 라인 |
| 구획 | — | 벽·구역 선·바닥 테두리로 닫혀 나뉜 바닥 한 덩어리. 이름을 붙이면 구역이 된다 | 영역, 칸, 셀, 섹터, 존 |
| 구역 기준점 | `roomAnchors` | 구역이 붙은 구획 안의 한 점. 벽·구역 선을 고쳐도 이 점이 든 구획이 그 구역이다 | 시드, 씨앗점, 앵커 |
| 바닥 | `floor` | 공간을 만들 때 정한 평면. 그대로 3D 바닥이 됨 | 캔버스 크기, 맵 크기, 그라운드 |
| 벽 | `Wall` | 그리기 도구로 만든 선의 묶음 | 라인, 파티션 |
| 점 | `Point` | 벽을 이루는 좌표 하나 (cm) | 꼭짓점, 노드, 버텍스 |
| 선분 | — | 두 점을 이은 선. 3D에서 벽 박스 하나가 됨 | 엣지, 세그먼트, 라인 |
| 가구 | `Box` | 공간에 배치한 모든 수납 물체 | 상자, 오브젝트, 박스, 아이템 |
| 가구 종류 | `FurnitureType`, `type` | 양문 수납장, 서랍장, 선반, 벽걸이, 책상, 테이블, 침대, 보관함 | 타입, 유형, 카테고리 |
| 보관함 | `"box"` | 가구 종류 중 하나. 가구를 처음 놓으면 기본으로 보관함 | 기본 상자, 상자 |
| 칸 | `slot` | 가구 안에서 물건을 넣는 한 자리 | 슬롯, 층, 단, 서랍칸, 섹션 |
| 칸 수 | `rows`, `cols` | 가구의 세로·가로 칸 개수 | 층수, 단수 |
| 칸 높이 | `rowHeights` | 칸마다 따로 정한 높이 (cm) | 층 높이, 단 높이 |
| 설치 높이 | `elevation` | 가구가 바닥에서 떠 있는 높이 (cm) | 고도, 오프셋, z값 |
| 받침 가구 | `parentId`가 가리키는 가구 | 다른 가구를 위에 올린 가구 | 부모, 베이스 |
| 가구 위 가구 | `parentId`가 있는 가구 | 다른 가구 위에 올린 가구 | 자식, 스택, 적층 |
| 정면 | `rotation` | 서랍·문이 달린 쪽. 회전으로 방향을 바꿈 | 앞방향, 프론트, 방향각 |
| 물건 | `Item` | 사용자가 칸에 넣은 것. 이름은 자유 | 아이템, 소지품, 항목, 객체 |
| 메모 | `memo` | 물건에 덧붙인 짧은 설명 | 노트, 설명, 비고 |

> 화면 문구에서는 칸을 가구 종류에 맞게 부른다: 서랍장 "위에서 2번째 서랍", 선반 "위에서 3번째 선반". 이것은 **사용자에게 보이는 표현**이고, 주석·README·커밋에서는 항상 "칸"이라고 쓴다.

## 화면 · 기능

| 쓰는 말 | 뜻 | 쓰지 않는 말 |
|---|---|---|
| 메인 화면 | 검색창 + 3D 공간이 있는 기본 화면 | 홈, 찾기 모드, 뷰어 |
| 편집 모드 | 벽·가구를 만들고 고치는 화면 | 에디터, 수정 화면, 만들기 모드 |
| 첫 실행 화면 | 공간이 하나도 없을 때 보이는 화면 | 온보딩, 빈 화면, 시작 화면 |
| 2D 평면도 | 편집 모드의 위에서 본 그리기 화면 | 캔버스, 도면, 맵 |
| 3D 미리보기 | 편집 모드에서 보는 3D | 3D 뷰, 프리뷰 |
| 3D 공간 | 메인 화면의 3D | 3D 씬, 3D 맵 |
| 그리기 도구 | 선택, 직선, 연속선, 사각형, 구역 선, 가구, 지우개 | 툴, 브러시 |
| 가구 상세 패널 | 가구를 누르면 열리는 칸별 물건 목록 | 정면도, 사이드바, 팝업, 상세창 |
| 속성 패널 | 편집 모드에서 선택한 가구의 이름·종류·크기를 바꾸는 패널 | 설정창, 인스펙터 |
| 공간 전환 | 메인 화면에서 다른 공간으로 바꾸는 것 | 방 바꾸기, 스위치 |
| 검색 | 물건 이름·메모로 찾는 것 | 찾기, 서치, 조회 |
| 검색 결과 카드 | "요깃따!"와 위치 문장이 나오는 카드 | 결과창, 결과 팝업 |
| 위치 문장 | "여권은 내 방의 화장대 서랍장 …에 보관 중이에요" | 결과 문구, 안내 문장 |
| 위치 표시 | 검색 후 3D에서 칸 열림·핑·핀으로 보여주는 것 | 하이라이트, 마킹 |
| 칸 열림 | 물건이 든 칸이 앞으로 빠져나오는 표시 | 서랍 오픈, 팝아웃 |
| 핑 | 가구 바닥의 점선 원 | 링, 원 표시 |
| 핀 | 칸 위에 꽂히는 이름 라벨 | 마커, 태그, 말풍선 |
| 흐리게 | 찾은 가구 외 나머지를 옅게 하는 것 | 디밍, 비활성 |
| 스냅 | 점이 격자·끝점에 붙는 것 | 자석, 맞춤 |
| 길이 표시 | 그리는 동안 미리보기 선 옆에 뜨는 지금 길이 ("1.2 m") | 치수선, 자, 측정 |
| 돋보기 | 터치로 끄는 동안 손가락 위에 뜨는, 손가락 아래를 확대한 둥근 창 | 루페, 확대경, 줌 창 |
| 되돌리기 / 다시하기 | Undo / Redo | 실행 취소, 복구 |

| 샘플 공간 | 처음 접속하면 보이는 예시 공간 | 데모, 예제 집, 기본 데이터 |
| 데이터 버전 | `version` 값과 그 변환 | 스키마 버전 |

## 작업 관리

| 쓰는 말 | 뜻 | 쓰지 않는 말 |
|---|---|---|
| 큰 Todo (`Tn`) | 전체 과정을 미리 나눈 큰 작업. `docs/TODO.md`에 한 줄씩 | 태스크, 작업 항목, 에픽 |
| 세부 Todo (`Tn-n`) | 커밋 단위 작업 (30분~2시간). 큰 Todo를 시작할 때 쓴다 | 서브태스크, 하위 작업 |
| 세부 Todo 파일 | 큰 Todo 하나의 세부 Todo를 적는 `docs/todo/Tn.md` | 하위 문서, 상세 Todo |
| 완료 기준 | 큰 Todo가 끝났다고 보는 상태 (PRD 인수 조건에서) | 종료 조건, DoD |
| 완료 조건 | 세부 Todo가 통과해야 할 테스트 (정상 + 엣지 케이스) | 체크 조건, 수용 기준 |
| 챕터 | 큰 Todo를 만드는 순서(의존 순서)대로 묶은 단계 (1. 기반 … 7. 다듬기) | 일차, 스프린트, 페이즈 |
| 목표 | 챕터가 끝나면 도달할 상태 (할 일이 아님) | 마일스톤, 골 |
| 오늘 할 일 | 그날 꼭 끝낼 세부 Todo 1~3개 (MIT) | 데일리, 오늘 목표 |
| Todo 변경 로그 | Todo 변경과 버그수정·오류수정을 큰 Todo별로 적는 `docs/todo/log/Tn.md` (여러 개에 걸치면 `전체.md`) | 변경 이력, 체인지로그, 수정 기록 |
| 버그수정 / 오류수정 | `commit-convention` 5장 정의 그대로 | 픽스, 핫픽스, 에러 수정 |
| 정리 점검 | 큰 Todo 끝난 뒤 코드 정리 | 리팩토링 타임, 클린업 |
| 코드 테스트 | Vitest로 순수 함수를 검사하는 것 (`npm run test`) | 단위 테스트, 유닛 테스트 |
| 실제 테스트 | Playwright로 브라우저를 열어 화면을 누르고 확인하는 것 (`npm run test:e2e`) | E2E, 통합 테스트, 화면 테스트 |
| 배포 확인 | 배포 주소에서 실제 테스트를 돌리는 것 | 운영 테스트, 스모크 |
| 직접 확인 | 사용자가 체크리스트를 보고 직접 눌러보는 것 | 수동 테스트, QA |
| 엣지 케이스 | 경계값·빈 값·잘못된 입력·실패 상황처럼 흔하지 않은 경우 | 예외 케이스, 코너 케이스 |
| 완료 | 세부 Todo의 테스트를 모두 통과한 상태 (`yogitta-test` 1장) | 끝, 구현 완료 |

## 문장 규칙

- 주석·README는 "~한다"체로 통일 (화면 문구만 "~해요"체)
- 영어 용어는 코드 이름을 가리킬 때만 백틱으로: `Box`, `rowHeights`
- 단위는 항상 cm, 숫자 뒤에 붙여 쓴다: 90cm, 6.0 × 4.5 m(바닥 크기와 길이 표시만 m)
