# 요깃따 (Yogitta) — 기획서

> 내 방 구조를 그림판처럼 그려서 3D로 세우고, 가구 속 물건 위치를 기록해두는 브라우저 앱
> "저번에 여권 어디 뒀더라?" → **"요깃따! 여권은 내 방의 화장대 서랍장 위에서 2번째 서랍에 보관 중이에요."**

---

## 1. 프로젝트 개요

### 1.1 한 줄 소개
2D 평면도에 벽을 그리고 가구를 배치하면 3D 공간이 만들어지고, 가구 안에 넣어둔 물건을 검색하거나 3D 화면에서 클릭해서 위치를 확인하는 앱.

### 1.2 만든 이유 (해결하는 문제)
- 충전기, 여권, 보조배터리, 계절 옷처럼 **가끔 쓰는 물건일수록 어디 뒀는지 기억이 안 남**
- 메모장에 적어두면 "어디"를 글로만 설명해야 해서 직관적이지 않음
- 실제 내 방 구조 그대로 3D로 보면서 위치를 찾을 수 있으면 훨씬 빠르게 찾을 수 있음

### 1.3 과제 조건 대응
| 조건 | 대응 |
|---|---|
| 브라우저 실행 | Vite + React 정적 사이트, GitHub Pages 배포 |
| 서버 없음 | 모든 데이터는 브라우저(localStorage) 저장 + 백업 파일 |
| 주기적 push | Todo 단위로 커밋, 커밋 메시지에 Todo 번호 표기 |
| Todo 변경 내역 | 기획 단계 변경 내역(7장) + 개발 중 변경 기록 |

## 2. 핵심 컨셉

### 2.1 기본 흐름
```
벽 그리기 → 가구 배치 → 가구 종류 지정 → 물건 등록 → 검색 / 3D 클릭으로 찾기
```

### 2.2 설계 원칙
| 대상 | 원칙 | 이유 |
|---|---|---|
| **벽** | 그림판처럼 자유롭게, 모든 도형은 점 목록으로 저장 | 내 방 구조 그대로 표현 |
| **바닥** | 처음 그리는 평면 전체가 바닥 | 닫힌 영역 판정 같은 복잡한 계산 제거 |
| **가구** | 종류·이름·구역을 **엄격하게** 관리 | 검색 문장이 정확해야 의미 있음 |
| **물건** | 이름 **자유**, 분류·태그 없음 | 사용자가 부르는 이름 그대로 기록 |
| **위치 판정** | 좌표 계산 없이 **가구 기준** | 가구를 옮기거나 벽을 바꿔도 물건 정보 유지 |

## 3. 기능 명세

### 3.1 공간 만들기
- 새 공간을 만들 때 **바닥 크기 입력** (예: 12m × 9m)
- 입력한 크기만큼 격자 평면 생성 → 이 평면이 그대로 3D 바닥이 됨
- 구역 목록 관리: 안방, 거실, 작은방 등 추가 / 이름 변경 / 삭제 (선택 사항)

### 3.2 벽 그리기 (편집 모드의 2D 평면도)
그림판 방식 도구로 평면도를 그림.

| 도구 | 저장 방식 | 3D 변환 |
|---|---|---|
| 직선 | 점 2개 | 벽 1개 |
| 연속 직선 | 점 n개 | 벽 n-1개 |
| 사각형 | 점 4개 (닫힘) | 벽 4개 |
| 원 *(3순위)* | 중심 + 반지름 → 점 32개로 분할 | 곡면처럼 보이는 벽 32개 |
| 곡선 *(3순위)* | 베지어 → 점 20개로 분할 | 곡면 벽 |
| 지우개 / 선택 | — | — |

편의 기능
- **격자 스냅**: 점이 격자(10cm 단위)에 붙음
- **끝점 스냅**: 기존 벽 끝 근처에서 점이 붙어 벽이 끊기지 않음
- **각도 고정** *(3순위)*: Shift 누르면 0°/45°/90°만
- **길이 표시** *(3순위)*: 그리는 중 "3.2m" 표시
- **되돌리기 / 다시하기**

### 3.3 3D 변환
- 바닥: 바닥 평면 = `PlaneGeometry`
- 벽: 선분 하나 = 얇고 긴 박스 하나
  - 길이 = 두 점 사이 거리
  - 회전 = `atan2(dy, dx)`
  - 위치 = 두 점의 중점
  - **2D의 y좌표 = 3D의 z좌표**
- 벽 모서리 이음새: 꺾이는 지점에 작은 기둥 박스로 틈 가리기 *(2순위)*
- 카메라: 회전 / 줌 / 이동 (OrbitControls)
- 2D 평면도 ↔ 3D 미리보기 전환

### 3.4 가구 (보관함 → 종류 지정 시 모양 변신)
1. 2D 평면도에서 사각형 드래그 → **보관함**으로 가구 생성
2. 가구에 **구역 선택(선택 사항)**, 이름 자동 부여 (`서랍장 1`, `서랍장 2` …)
3. **종류 지정** → 가구 크기(가로·깊이·높이) 그대로 해당 종류 모양으로 변신
4. 크기를 바꾸면 모양도 따라서 늘어나고 줄어듦

기본 가구 8종 (MVP)
| 종류 | 코드 | 모양 구성 | 칸 표현 | 기본 높이 | 칸 높이 조절 |
|---|---|---|---|---|---|
| 양문 수납장 | `cabinet` | 외곽 + 문 2짝 + 안쪽 선반 n칸 | 왼쪽/오른쪽 문 · 위에서 n번째 칸 | 180cm | ✅ |
| 서랍장 (층형) | `drawer` | 외곽 + 서랍 n칸 + 손잡이 | 위에서 n번째 서랍 | 90cm | ✅ |
| 선반 | `shelf` | 옆판·뒤판 + 선반 n칸 (앞 뚫림) | 위에서 n번째 선반 | 180cm | ✅ |
| 벽걸이 | `wall` | 벽에 붙는 얇은 선반/수납장, 바닥에서 떠 있음 | 위에서 n번째 칸 | 60cm (설치 높이 150cm) | ✅ |
| 책상 | `desk` | 상판 + 다리 4개 | 상판 위 | 73cm | — |
| 테이블 | `table` | 상판 + 다리 4개 (책상보다 넓고 낮음) | 테이블 위 | 72cm | — |
| 침대 | `bed` | 프레임 + 매트리스 + 머리판 | 침대 위 / 침대 밑 | 45cm | — |
| 보관함 | `box` | 박스 1개 (가구를 처음 놓을 때 기본 종류) | 보관함 안 | 40cm | — |

> 벽걸이는 보통 **벽 선반**(앞이 뚫린 것) 또는 **상부장/벽걸이 수납장**(문 달린 것)이라고 부른다. MVP에선 하나로 묶고 이름은 "벽걸이"로 한다.
> 기존 계획의 옷장은 **양문 수납장**으로 통합한다.

**가구 위에 가구 올리기**
- 가구를 다른 가구 위에 올릴 수 있음 (예: 책상 위 보관함, 서랍장 위 선반)
- 2D 평면도에서 가구를 다른 가구 위로 드래그하면 **"위에 올리기"** 로 붙고, 설치 높이 = 받침 가구 높이로 자동 설정
- 받침 가구를 옮기면 가구 위 가구도 같이 따라감 (`parentId` 관계)
- 검색 문장에 반영: "충전기는 내 방의 **책상 위 보관함** 안에 있어요"
- 받침 가구를 삭제하면 가구 위 가구는 바닥으로 내려갈지 같이 삭제할지 선택

**칸 높이 직접 입력** (양문 수납장 · 서랍장 · 선반 · 벽걸이)
- 전체 크기(가로·깊이·높이) 말고도 **칸마다 높이**를 따로 입력 가능 (예: 선반 1번째 칸 40cm, 2번째 칸 25cm, 3번째 칸 35cm)
- 기본값은 전체 높이를 칸 수로 균등 분배, 하나를 바꾸면 합계가 전체 높이를 넘지 않게 경고
- 3D 모양도 입력한 칸 높이대로 선반·서랍 선이 그려짐

**벽걸이 규칙**
- 배치 시 가장 가까운 벽에 등이 붙도록 스냅 + 정면은 공간 안쪽
- **설치 높이(바닥에서 cm)** 필수 입력

규칙
- 종류는 **정해진 목록에서만** 선택
- 가구 이름 **중복 불가** ("이미 '화장대 서랍장'이 있어요")
- 판 두께·다리 굵기·손잡이는 **cm 고정값** (비율로 하면 큰 가구가 어색해짐)
- **정면 방향** 표시 (서랍·문이 달린 쪽), 회전으로 조절
- 종류 변경 시 "기본 높이 적용" 선택 가능
- 2D/3D 모두 가구 위에 **이름 라벨** + 물건 개수 뱃지

### 3.5 물건 등록
- 입력: **이름(자유)** + 칸 선택 + 메모(선택)
- 분류·태그 없음
- 한 가구, 한 칸에 **여러 개** 등록 가능
- 칸을 지정하지 않으면 "칸 없음"으로 저장
- 물건 이동: 칸 ↔ 칸, 가구 ↔ 가구 *(2순위)*
- 칸 수가 줄어들면 사라진 칸의 물건은 "칸 없음"으로 이동 + 알림
- 가구 삭제 시 안에 물건이 있으면 경고 → 같이 삭제 / 다른 가구로 이동 선택

### 3.6 가구 상세 패널
가구를 선택하면 열리는 패널. 검색과 3D 클릭이 **같은 패널**을 사용.

```
┌──── 화장대 서랍장 ────┐
│ 📍 안방 · 침대 옆        │
│ 물건 5개                │
├──────────────────────┤
│ [1번째 칸] 여권 · 보조배터리 · 충전기 │
│ [2번째 칸] 양말                │
│ [3번째 칸] 비어 있어요  [+ 추가]  │
│ [칸 없음] 선글라스          │
└──────────────────────┘
```
- 칸별 물건 목록, 추가 / 삭제 / 이동
- 모바일에서는 하단 시트로 표시

### 3.7 찾기 ① 검색 (이름 → 위치)
- 검색 범위: 물건 이름 + 메모
- 부분 일치 ("패딩" → "작년 겨울 패딩"), 띄어쓰기 무시
- 결과 문장 자동 조합:
  ```
  [물건]은/는 [공간]의 [가구 이름] [칸 위치]에 보관 중이에요.
  ```
  - 받침 판별로 **은/는 자동 처리**
  - 칸 위치는 가구 종류별 표현 사용 (3.4 표 참고)
- **같은 칸에 있는 물건 함께 표시**
  - 혼자 있으면 "이 칸엔 여권만 있어요"
  - 5개 이상이면 앞 4개 + "외 n개"
  - 물건 이름 클릭 → 그 물건 검색 결과로 이동
- 같은 이름 물건이 여러 곳이면 목록으로 표시
- **찾으면 "요깃따!"** — 결과 카드 맨 위에 앱 이름이자 감탄사로 크게 표시 (+ "'여권' 1곳 찾음")
- 결과 없음: "아직 어딨는지 몰라요. '여권' 지금 등록할까요?"
- 결과 클릭 → 3D 카메라가 해당 가구로 이동 + 위치 표시 + 가구 상세 패널에서 해당 칸 강조

**3D 위치 표시** (검색하면 3D 공간에 바로 보이게)
- 찾은 가구만 강조색, **나머지 가구는 흐리게** 처리해서 눈이 바로 가게
- 물건이 든 칸이 **칸 열림**으로 앞으로 빠져나오고, 안에 물건 표시
- 가구 바닥에 **점선 원(핑)** 표시
- 핀 라벨: 물건 이름 + "화장대 서랍장 · 2번째 서랍"
- 칸 지정이 없는 물건은 가구 전체만 강조, 같은 이름이 여러 곳이면 핀 여러 개

검색 결과 예시
```
🔍 여권

요깃따!   '여권' 1곳 찾음

여권은 내 방의 화장대 서랍장 위에서 2번째 서랍에 보관 중이에요.
📝 파란 파우치 안

같은 칸에 있는 물건
보조배터리 · 충전기

[3D에서 보기]
```

### 3.8 찾기 ② 3D 클릭 (위치 → 내용물)
- 마우스 올리면 가구가 살짝 밝아지고 이름 라벨 표시
- 클릭하면 카메라가 부드럽게 이동 + 테두리 강조 + 가구 상세 패널 열림
- **회전 드래그와 클릭 구분**: 이동 거리가 일정 이하일 때만 클릭 처리
- **벽은 클릭 판정에서 제외** (가구가 벽에 가려져도 선택 가능)
- 2D 평면도에서 클릭해도 같은 패널

### 3.9 저장
- localStorage 자동 저장 — 키 이름 `yogitta:v1`
  - GitHub Pages는 같은 계정의 다른 프로젝트와 저장소(origin)를 공유하므로 **앱 고유 접두사 필수**
  - 데이터에 `version`을 넣어 구조가 바뀌면 변환 함수로 옛 데이터를 살림
- **백업 파일 내보내기 / 가져오기** (JSON, 브라우저·기기 이동)
- **샘플 공간**: 처음 열면 예시 원룸이 깔려 있어 바로 체험 가능

## 3.10 화면 구조 (모드 분리)

찾는 일이 대부분이므로 **메인 화면**과 **편집 모드**(만들기·수정)를 분리한다.

### ① 메인 화면 (기본)
```
┌─────────────────────────────────┐
│ 🏠 요깃따                   [✏️ 편집] │
│ ┌─────────────────────────────┐ │
│ │ 🔍 무엇을 찾고 있나요?          │ │
│ └─────────────────────────────┘ │
│                                 │
│         3D 공간                  │
│     (회전 / 줌 / 가구 클릭)        │
│                    ┌──────────┐ │
│                    │ 가구 상세   │ │
│                    └──────────┘ │
└─────────────────────────────────┘
```
- 상단: 검색창만. 아래: 3D 공간
- 그리기 도구·구역 목록 등은 숨김
- 할 수 있는 것: 검색, 3D 둘러보기, 가구 클릭, **물건 추가/수정/삭제/이동**

### ② 첫 실행 화면 (공간이 없을 때)
- 화면 중앙에 `+` 버튼 + "아직 공간이 없어요. 만들어볼까요?"
- `+` → 바닥 크기 입력 → 편집 모드의 2D 평면도
- [샘플 공간 둘러보기] 버튼 제공

### ③ 편집 모드 (만들기 = 수정, 같은 화면)
```
┌─────────────────────────────────┐
│ ← 완료   편집 모드   [2D | 3D 미리보기]   │
├────┬────────────────────────────┤
│↖ 선택│                            │
│／ 직선│       2D 평면도               │
│⬜ 사각│                            │
│📦 가구│                            │
│⌫ 지우개│                            │
├────┴────────────────────────────┤
│ 구역: [안방] [거실] [+]    ↶ ↷        │
└─────────────────────────────────┘
```
- 처음 만들기와 수정이 **같은 2D 평면도·같은 그리기 도구**
- 메인 화면의 `✏️ 편집` → 현재 공간을 불러와 수정
- `← 완료` → 저장 후 메인 화면으로 복귀

### ④ 공간 여러 개 (내 방 → 형 방 전환)
- 구조(벽·가구·물건 한 세트)를 **"공간"** 단위로 여러 개 만들 수 있음 (예: 내 방, 형 방, 거실·주방)
- 메인 화면 상단 **공간 버튼(`내 방 ▾`)** → 목록에서 골라 바로 전환, 화면 구성은 그대로
- 목록 항목: 미니 3D 썸네일 + 이름 + 크기 · 가구 수 · 물건 수, 맨 아래 `+ 새 공간 만들기`
- 검색은 **현재 공간 우선**, 다른 공간에서도 찾으면 검색 결과 카드에 "다른 공간에도 있어요: 형 방 1곳" 링크 → 누르면 그 공간으로 전환
- 편집 모드는 현재 선택된 공간만 편집
- 공간 이름 변경 · 복제 · 삭제는 목록에서

### 수정 기능 (필수)
| 대상 | 수정 가능한 것 | 위치 |
|---|---|---|
| 벽 | 삭제, 점 드래그로 모양 변경 | 편집 |
| 가구 | 이동, 회전, 크기, 종류, 이름, 구역, 칸 수 | 편집 |
| 구역 | 이름 변경, 삭제 | 편집 |
| 바닥 | 크기 변경 | 편집 |
| 물건 | 이름, 메모, 칸 이동, 다른 가구로 이동 | 메인 (가구 상세 패널) |

- 모든 수정은 되돌리기 / 다시하기 가능 → **되돌리기 / 다시하기를 1순위로 상향**
- 원칙: **물건은 메인에서, 구조는 편집에서** (물건 관리 중 구조를 실수로 건드리지 않도록)

## 4. 데이터 구조

```ts
type Point = { x: number; y: number }; // cm 단위

type Wall = {
  id: string;
  tool: "line" | "polyline" | "rect" | "circle" | "curve";
  points: Point[];   // 원·곡선도 최종적으로 점 목록으로 변환
  closed: boolean;
};

type FurnitureType =
  | "cabinet" | "drawer" | "shelf" | "wall"   // 칸 높이 조절 가능
  | "desk" | "table" | "bed" | "box";

type Item = {
  id: string;
  name: string;      // 자유 입력
  slot?: number;     // 칸 번호 (없으면 칸 없음)
  memo?: string;
};

type Box = {
  id: string;
  name: string;           // 중복 불가
  type: FurnitureType;    // 정해진 목록만
  room?: string;          // 구역 (선택)
  x: number; z: number;   // 바닥 위 중심 위치
  rotation: number;       // 정면 방향
  w: number; d: number; h: number; // cm
  elevation: number;      // 설치 높이 (cm). 벽걸이·가구 위 가구용
  parentId?: string;      // 가구 위 가구면 받침 가구 id
  rows: number; cols: number;
  rowHeights?: number[];  // 칸별 높이 (cm). 없으면 h를 rows로 균등 분배
  items: Item[];
};

type Space = {            // 공간 하나 = 구조 한 세트 (내 방, 형 방 …)
  id: string;
  name: string;           // 중복 불가
  floor: { w: number; h: number }; // cm
  rooms: string[];        // 공간 안 구역 이름 (선택)
  walls: Wall[];
  boxes: Box[];
};

type AppData = {
  version: 1;             // 데이터 버전
  spaces: Space[];
  currentSpaceId: string; // 지금 보고 있는 공간
};
```

계층
```
전체 데이터 (AppData)
 └ 공간 (Space)       ← 이름, 바닥, 구역 목록
    ├ 벽 (Wall)
    └ 가구 (Box)      ← 구역, 위치, 크기, 종류
       └ 물건 (Item)  ← 이름, 칸, 메모
```

데이터 모델의 기준은 `docs/PRD.md` 부록 B다.

- 벽에 가려진 가구 클릭 불가
- 모바일 드래그·3D 성능 문제
- 부분 일치 검색 정확도

## 8. 사용할 스킬

세 스킬 모두 직접 만들었고 `.claude/skills/` 아래에 있다. 세 스킬이 함께 쓰는 용어집은 `.claude/skills/yogitta-code/glossary.md`다.

| 스킬 | 구분 | 용도 | 이유 |
|---|---|---|---|
| `yogitta-code` | 직접 제작 | 폴더 구조(feature 단위), 의존 방향, 로직·상태·화면 분리, 이름·크기·타입 규칙, 상수(단위 cm, 2D y = 3D z), 꼭 테스트할 순수 함수, 작업 흐름(계획 → 작성 → 자가 점검 → `npm run check` → 커밋), 정리 점검 + 용어집 | 프로젝트가 커져도 어디에 뭐가 있는지 바로 알고, 한 기능을 고쳐도 다른 기능이 깨지지 않게. **프로젝트 핵심 스킬** |
| `yogitta-design` | 직접 제작 | B안 "미니어처 하우스" 색 토큰, 글꼴(Jua·Gowun Dodum), 컴포넌트 모양, 3D 색·면 음영, 위치 표시 순서, 2D 평면도 모양, 레이아웃, 문구 톤, 접근성 | 화면마다 색·모양이 달라지지 않게 시안(`docs/design/`)을 수치 규칙으로 고정 |
| `commit-convention` | 직접 제작 | 세부 Todo 단위 커밋 `Tn-n: 작업 내용`, `Tn-n 버그수정[영역]` / `Tn-n 오류수정[영역]`, `todo:` 커밋, README용 로그 뽑기 | 과제의 커밋 조건(중간중간 push, 커밋 내역에 한 일이 보이게) 충족 + Todo 변경 내역 추적 |

> 실제 사용 후 README에 각 SKILL.md 내용과 작업에서 쓰인 방식을 기록한다.
