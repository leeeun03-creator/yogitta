# 요깃따 (Yogitta) PRD

요깃따는 내 방을 2D로 그려 3D로 세우고, 물건을 검색하면 그 칸이 열리며 "요깃따!" 하고 위치를 보여주는 브라우저 앱이다.

| 항목 | 내용 |
| --- | --- |
| 문서 | PRD v0.4 (초안) |
| 프로젝트 | 바이브 코딩 수업 중간고사 과제 |
| 실행 환경 | 브라우저 (GitHub Pages, 서버 없음) |
| 제작 기간 | 1주 |
| 관련 자료 | `docs/기획서.md`, `yogitta-design` 스킬의 `references/` (B안 미니어처 하우스) |

**한눈에 보기**

- 문제: 가끔 쓰는 물건일수록 어디 뒀는지 기억이 안 나고, 글로 적은 메모는 "어디"를 직관적으로 보여주지 못한다
- 해결: 실제 방 구조와 가구를 3D로 재현하고, 물건을 가구의 칸 단위로 기록한다
- 핵심 경험: 검색 → 해당 칸이 열리고 핀이 꽂힘 → "요깃따!" + 위치 문장 + 같은 칸 물건
- 범위: 공간 여러 개(내 방, 형 방…), 가구 8종, 가구 위 가구, 칸 높이 입력, 로컬 저장
- 제외: 로그인, 서버 동기화, 사진 인식

## 1. 개요와 배경

물건 위치를 기억에만 의존하면 결국 서랍을 하나씩 다 열어보게 된다. 요깃따는 "어디"를 글이 아니라 내 방 모습 그대로 보여줘서 찾는 시간을 줄이는 것이 목적이다.

수업 과제 조건(브라우저 실행, GitHub 공개 저장소, Todo 기반 주기적 커밋)에 맞춰 서버 없는 정적 웹앱으로 만든다. 그래픽스 수업에서 배운 좌표 변환과 Three.js를 실제 기능에 적용하는 것도 목표 중 하나다.

## 2. 문제 정의

가끔 쓰는 물건(여권, 충전기, 계절 옷, 보조배터리)은 넣어둔 순간에는 기억하지만 몇 달 뒤엔 위치를 잊는다.

| 상황 | 지금의 불편 |
| --- | --- |
| 여행 전날 여권을 찾을 때 | 서랍·수납장을 차례로 다 열어봄 |
| 가족 방에 둔 물건을 찾을 때 | 직접 물어보거나 남의 방을 뒤져야 함 |
| 메모 앱에 "책상 서랍"이라고 적어둘 때 | 어느 책상, 몇 번째 서랍인지 애매함 |
| 사진으로 남겨둘 때 | 사진이 쌓이면 검색이 안 되고, 위치 맥락이 없음 |

근거: 개인 경험 기반이며, 같은 문제를 다루는 앱(WDIPI, Nestmer 등)이 꾸준히 출시되는 것도 수요가 있다는 신호다. 다만 기존 앱은 글 경로나 사진까지만 보여주고 칸 단위 3D 위치는 보여주지 않는다 (부록 A).

## 3. 목표와 성공 지표

성공 = 처음 쓰는 사람이 샘플 공간에서 물건 하나를 10초 안에 찾고, 자기 방을 10분 안에 만들 수 있는 것.

| 목표 | 지표 | 기준 |
| --- | --- | --- |
| 빠르게 찾기 | 검색어 입력 → 3D 위치 표시까지 | 1초 이하 (물건 500개 기준) |
| 처음이어도 쉽게 | 샘플 공간에서 "여권" 찾기 성공 | 테스트 참가자 5명 중 5명 |
| 내 방 만들기 | 벽 + 가구 5개 + 물건 10개 등록 시간 | 10분 이하 |
| 정확한 위치 | 위치 문장이 가구 이름 + 칸까지 포함 | 칸 지정 물건 100% |
| 데이터 안전 | 새로고침·재접속 후 데이터 유지 | 100% |
| 과제 조건 | 브라우저 실행, 공개 저장소, Todo별 커밋 | 모두 충족 |

**하지 않을 것 (Non-goals)**

- 로그인, 계정, 서버 저장, 기기 간 자동 동기화
- 가족과 실시간 공유 (백업 파일 공유로 대체)
- 사진으로 물건 자동 인식, AI 추천
- 실제 인테리어 수준의 정밀 3D (조명·재질·가구 모델 불러오기)
- 물건 가격·구매일 같은 재산 관리 기능

## 4. 타깃 사용자

주 사용자는 자기 방 물건이 많은 대학생·자취생, 부 사용자는 가족과 같이 사는 사람과 과제 평가자다.

| 구분 | 페르소나 | 상황 | 바라는 것 |
| --- | --- | --- | --- |
| 주 사용자 | 자취하는 대학생 "은이" | 원룸에 수납장·서랍장·선반이 빽빽함. 시험 기간엔 충전기, 방학엔 여권을 찾음 | 검색 한 번에 "몇 번째 서랍"까지 |
| 부 사용자 | 형제와 사는 사람 | 형 방에 둔 공구를 자주 찾음 | 공간(내 방 / 형 방)을 바꿔가며 보기 |
| 부 사용자 | 과제 평가자(교수님) | 링크만 받아서 바로 확인 | 설치·가입 없이 샘플 공간으로 바로 체험 |

**비기능 요구사항**

- 성능: 가구 50개 공간에서 3D 회전 30fps 이상(노트북 기준), 검색 1초 이하
- 호환성: 최신 크롬·엣지·사파리, 화면 폭 360px까지 (모바일은 하단 시트)
- 개인정보: 데이터는 사용자 브라우저에만 저장, 서버 전송 없음
- 저장: 키 `yogitta:v1`, 데이터에 `version` 포함, 같은 github.io 계정의 다른 앱과 충돌 방지
- 접근성: 터치 영역 44px 이상, 본문 대비 4.5:1 이상, 아이콘 버튼에 이름(aria-label)
- 빈 상태·오류: 공간 없음, 검색 결과 없음, 저장 실패(용량 초과) 화면 정의

## 7. 인수 조건

각 P0 기능은 아래 조건을 모두 통과하면 완료다.

| 기능 | Given (상황) | When (행동) | Then (결과) |
| --- | --- | --- | --- |
| 검색 (F8·F9) | "여권"이 화장대 서랍장 2번째 칸에 있을 때 | "여권"을 검색하면 | "요깃따!"와 "여권은 내 방의 화장대 서랍장 위에서 2번째 서랍에 보관 중이에요"가 보인다 |
| 부분 일치 (F8) | "작년 겨울 패딩"이 등록돼 있을 때 | "겨울패딩"을 검색하면 | 해당 물건이 결과에 나온다 |
| 결과 없음 (F9) | 등록되지 않은 이름일 때 | 검색하면 | "아직 어딨는지 몰라요"와 등록 버튼이 보인다 |
| 3D 위치 표시 (F10) | 검색 결과가 칸 지정 물건일 때 | 결과를 누르면 | 카메라가 가구로 이동하고, 그 칸만 열리며, 다른 가구는 흐려진다 |
| 가구 클릭 (F11) | 3D 공간에서 | 회전 없이 가구를 누르면 | 가구 상세 패널이 열리고, 드래그로 회전한 경우엔 열리지 않는다 |
| 벽 → 3D (F3) | 2D 평면도에서 사각형 벽을 그렸을 때 | 3D 미리보기로 바꾸면 | 같은 위치·길이로 벽 4개가 서 있다 |
| 가구 변신 (F4·F5) | 60×50×90cm 보관함이 있을 때 | 종류를 서랍장으로 바꾸면 | 같은 크기 안에서 서랍장 모양으로 바뀌고, 안의 물건은 유지된다 |
| 이름 중복 (F6) | "화장대 서랍장"이 이미 있을 때 | 같은 이름을 입력하면 | 저장이 막히고 안내 문구가 뜬다 |
| 공간 전환 (F12) | 내 방을 보고 있을 때 | 공간 목록에서 형 방을 고르면 | 화면 구성은 그대로, 형 방의 벽·가구·물건으로 바뀐다 |
| 되돌리기 (F13) | 가구를 옮긴 직후 | 되돌리기를 누르면 | 가구가 이전 위치로 돌아간다 |
| 저장 (F14) | 물건을 추가한 뒤 | 새로고침하면 | 추가한 물건이 그대로 있다 |
| 첫 접속 (F14) | 저장된 데이터가 없을 때 | 링크를 처음 열면 | 샘플 공간이 바로 보이고 검색이 된다 |
| 칸 수 감소 | 서랍장 4번째 칸에 물건이 있을 때 | 칸 수를 3으로 줄이면 | 그 물건이 "칸 없음"으로 옮겨지고 알림이 뜬다 |
| 가구 삭제 | 물건이 든 가구일 때 | 삭제하면 | "같이 지우기 / 다른 가구로 옮기기"를 묻는다 |

## 8. UX 플로우와 디자인

찾는 일이 대부분이라 메인 화면 하나에서 검색·공간 전환·가구 확인을 끝내고, 벽·가구 구조 수정만 편집 모드로 분리한다. 디자인은 3안(건축 도면 / 미니어처 하우스 / 미니멀)을 비교한 뒤 **B안 "미니어처 하우스"**로 확정했다. 레퍼런스 시안은 `yogitta-design` 스킬의 `references/`에 있다.

```
첫 실행 화면 ──(+)──▶ 바닥 크기 입력 ──▶ 편집 모드 ──(완료)──▶ 메인 화면
      └──(샘플 공간 둘러보기)──────────────────────────────▶ 메인 화면
메인 화면 ──(편집)──▶ 편집 모드
메인 화면 ─┬─(검색)──────▶ 검색 결과 카드 + 3D 위치 표시
          ├─(가구 클릭)──▶ 가구 상세 패널
          └─(공간 선택)──▶ 공간 전환 (내 방 → 형 방)
```

물건은 메인 화면에서, 벽·가구 구조는 편집 모드에서 다룬다. 물건을 정리하다 실수로 벽이나 가구를 건드리지 않게 하기 위해서다.

**화면별 핵심 요소** (시안: `yogitta-design` 스킬의 `references/01~05`)

| 화면 | 들어가는 것 |
| --- | --- |
| 메인 화면 | 로고, 공간 버튼(`내 방 ▾`), 편집 버튼, 알약형 검색창, 3D 공간, 시점·줌 버튼, 가구 상세 패널 |

## 10. 기술 스택

서버 없는 정적 웹앱이라 빌드 결과물(HTML·JS·CSS)만 GitHub Pages에 올린다. 외부 API와 서버는 없다.

| 영역 | 기술 | 버전 | 고른 이유 | 적용 |
| --- | --- | --- | --- | --- |
| 빌드 | Vite | 8.3 | 설정이 적고 개발 서버가 빠름, 정적 파일로 바로 빌드 | T1-2 |
| UI | React + TypeScript | React 19.3 / TS 6.0 | 화면을 컴포넌트로 나누기 쉽고, 타입으로 데이터 모델(부록 B)을 고정 | T1-2 |
| 코드 검사 | ESLint 9 + typescript-eslint, Prettier 3 | | 순환 import·feature 내부 import·`any`를 자동으로 막음 (`yogitta-code` 10장) | T1-3 |
| 테스트 | Vitest | 5.0 | Vite 설정을 그대로 써서 순수 함수(은/는, 검색 매칭, 선분 → 벽)를 빠르게 검사 | T1-3 |
| 스타일 | CSS 변수(`tokens.css`) + CSS Modules, Google Fonts(Jua·Gowun Dodum) | | 디자인 토큰을 한 곳에서 관리, 컴포넌트마다 스타일이 섞이지 않음 | T1-4 |
| 상태 | zustand | | 전체 데이터를 store 하나에 두고, 되돌리기 / 다시하기 스냅샷을 만들기 쉬움 | T2-2 |
| 아이콘 | lucide-react | | 선 아이콘 (`yogitta-design` 3장) | T2-3 |
| 2D 평면도 | SVG (라이브러리 없음) | | 선분·가구 사각형 클릭·드래그 처리가 쉽고, 줌·이동은 viewBox로 처리 | T2-5 |

| 저장 | localStorage + 백업 파일(JSON) | | 서버 없이 브라우저에 저장, 키 `yogitta:v1` | T11, T17 |
| 배포 | GitHub Pages + GitHub Actions | | `main`에 push하면 자동으로 빌드·배포 | T1-5 |

**버전을 고정한 이유**

- TypeScript는 7.0이 최신이지만 typescript-eslint가 6.1 미만만 지원해서 6.0으로 고정했다.
- ESLint는 10이 최신이지만 순환 import 검사에 쓰는 import resolver가 9까지만 지원해서 9로 고정했다.

## 11. 의존성, 리스크, 가정

**의존성**: 10장 기술 스택의 라이브러리와 Google Fonts, GitHub Pages. 외부 API와 서버는 없다.

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 마감 안에 다 못 끝냄 | 제출 불가 | P0만으로 제출 가능하게 설계, push마다 배포 상태 유지, 막히면 P1(가구 위 가구)부터 내림 |
| 2D 평면도 작업에 시간 과다 | 3D·검색 지연 | P0는 직선·연속선·사각형·지우개만, 원·곡선은 P2 |
| 2D y ↔ 3D z 축 혼동, 회전 기준점 | 가구가 엉뚱한 위치 | 좌표 규칙을 `yogitta-code` 상수·테스트로 고정 |
| 회전 드래그가 클릭으로 인식 | 패널 오작동 | 이동 거리 기준으로 클릭 판정 |
| 다른 가구에 가려 열린 칸이 안 보임 | 위치 표시 실패 | 나머지 가구 흐리게 + 카메라를 칸 정면으로 이동 |
| 브라우저 데이터 삭제 | 데이터 유실 | 백업 파일 안내 |
| 같은 github.io 계정의 다른 앱과 저장소 충돌 | 데이터 덮어씀 | 키 `yogitta:v1` 접두사 |

**가정**

- 사용자는 자기 방 대략적인 치수(cm)를 알고 있거나 줄자로 잴 수 있다
- 공간 하나에 가구 50개, 전체 물건 500개 이하 (localStorage 5MB로 충분)
- 평가는 노트북 크롬에서 이뤄진다

## 부록 B. 데이터 모델

```ts
type AppData = { version: 1; spaces: Space[]; currentSpaceId: string };

type Space = {
  id: string; name: string;            // 내 방, 형 방 (중복 불가)
  floor: { w: number; h: number };     // cm
  rooms: string[];                     // 공간 안 구역 (선택)
  walls: Wall[]; boxes: Box[];
};

type Wall = { id: string; tool: "line" | "polyline" | "rect" | "circle" | "curve"; points: { x: number; y: number }[]; closed: boolean };

type FurnitureType = "cabinet" | "drawer" | "shelf" | "wall" | "desk" | "table" | "bed" | "box";

type Box = {
  id: string; name: string; type: FurnitureType; room?: string;
  x: number; z: number; rotation: number;   // 바닥 위 중심, 정면 방향
  w: number; d: number; h: number;          // cm
  elevation: number; parentId?: string;     // 벽걸이·가구 위 가구
  rows: number; cols: number; rowHeights?: number[];
  items: Item[];
};

type Item = { id: string; name: string; slot?: number; memo?: string };
```

물건은 좌표가 아니라 가구(`Box`)에 속한다. 그래서 가구를 옮기거나 벽을 고쳐도 물건 위치 정보가 그대로 유지된다. 저장 키는 `yogitta:v1`이다.
